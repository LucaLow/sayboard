# Browser source release assembly

`python3 scripts/speech/release/assemble.py` creates ordinary public source GET assets in `public/source`. Run it before Vite so those assets are copied into `dist/source`. The Git build must run this hook on every release. Generated archives are not committed and model weights are excluded.

The root owner-authorized GPL combined frontend contains only browser modules, their build configuration and notices. The package uses an explicit path allowlist. It excludes the API/backend implementation, Git history/settings, environment files, source-decision planning documents, private records and audio generated during testing. Necessary upstream eSpeak pronunciation data remains in its own preferred-source archive.

The standalone source package removes the backend workspace and its unreachable dependencies by a deterministic dependency/optional/peer closure over the frozen lock. The full project's original backend is also open source under the policy in `LICENSING.md`; these archives remain focused on browser reproduction. No npm lock refresh, package resolution or platform metadata rewrite occurs. Its build script invokes TypeScript and Vite directly, without recursively embedding public archives. All browser modules and Vite settings are copied unchanged. `SOURCE-README.md` records these packaging changes.

`component-lock.json` pins preferred component source downloads by SHA-256. The fetcher rejects integrity mismatches. File links inside upstream tarballs become their preferred target contents; test-only directory links are omitted. Original source archives are normalized with sorted paths, fixed owners/timestamps and deterministic gzip headers. Component URLs use the actual normalized archive SHA-256, so unchanged preferred sources share an immutable URL across packaging-tool changes. The final frontend content hash selects an immutable release directory, while `/source/index.html` points to the current complete inventory. Preserve release-specific URLs for as long as the runtime is served. Do not clean archives from prior published releases.

The original Transformers SDK embeds dependencies that differ from installed current npm versions. Their preferred sources and matching build inputs are separately supplied, including flatbuffers25.1.24, guid-typescript1.0.9, long5.2.3, platform1.3.6, protobufjs7.2.6 and its handwritten submodules, and Jinja0.5.3. ORT's matching native sources, dependency sources, Emscripten4.0.4 runtime/musl and emsdk submodule are supplied. eSpeak has separate Emscripten3.1.64 sources. General compiler executables are not included.

Two upstream packaging differences are documented in the lock. Eigen's current ZIP bytes differ from its older ORT dependency hash; all 1,891 preferred-source file Git blob hashes were independently matched to the pinned commit. guid-typescript's npm-recorded commit is unavailable; rebuilding its accessible pinned source with TypeScript3.1.6 produces the identical published JS after restoring its original CRLF line endings. Its normalized JS SHA-256 is `71f9870d007cb6daf403c6d3a04b588a296911f1ae523296120b1920e7915e95`.

The assembly manifest is a source inventory, not a claim that the upstream ORT native binary has been locally rebuilt. eSpeak was independently rebuilt. A clean extracted frontend build must compare production `/assets` byte hashes with the release build before shipping. Independently inspect archive entries and contents for excluded paths, private data and source completeness. Verify public source endpoints with ordinary read-only HTTPS GET requests, never browser download/file-chooser actions.

Independent builds do not fetch the official Sayboard service. The default retention policy starts empty. The standalone server merges the new source tree into persistent `/data/source`, preserves previous immutable URLs across upgrades, and rejects changed bytes at an existing path. Back up this source tree with the installation's data.

For an instance migration, copy its existing retained source tree before serving an update. An optional `SAYBOARD_SOURCE_ORIGIN` can import prior releases from an exact HTTPS origin during assembly. `SAYBOARD_SOURCE_POLICY` selects that instance's expected release records. Redirects, unsafe paths, changed manifests and archive hash mismatches are rejected. No credentials are sent. Previously published source archives must not be discarded during migration.

`SOURCE_RETENTION_SEED` identifies a generated release and its manifest hash. Operators using remote acquisition can add it to their own policy file. It is not an application runtime input or a requirement to edit project code for a new independent installation.

For local runs, `SAYBOARD_SOURCE_CACHE` selects a verified download cache. The default is `node_modules/.cache/source`. Source fetches contain no user vocabulary, accounts or audio.
